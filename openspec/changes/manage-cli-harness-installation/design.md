# Design

The wizard's presentation catalog remains static generated data. A separate typed
installer registry is the execution authority for source-qualified terminal IDs.
Compiler checks bind that registry to the terminal catalog and mirror the same
runtime into personalized image contexts. Native/Python plan validation shares
those enabled IDs; catalog prose can never inject shell commands.

Installation owns one per-product prefix with immutable candidate directories,
a current symlink, a public launcher, an ownership lock and a private receipt.
Package/source identity and actual launcher verification precede atomic activation.
A second empty runtime home catches publisher launchers tied to staging paths.
Failures and cancellation preserve the previous current version. Removal validates
its complete owned boundary and is idempotent when already absent.

Tools runs workstation package operations through native callbacks; subprocesses
receive a staging home and explicit clean environment. Native platform/architecture
are queried natively. Callback leases and local process groups bound cancellation;
container cancellation is scoped to an operation marker, immutable container ID,
non-root user and process start identity. No provider credential adapter is added.

Reviewed bench install/update choices are explicit targets. Exact existing Docker
resource checks bind live execution without restarting sessions. Private desired
ID lists, isolated Layer 3 contexts and recipe fingerprints bind later image
recreation. An unavailable target is pending, not installed. Source-qualified
coverage, fixture success and live qualification are reported separately.

The source audit does not identify a trustworthy current Mentat installer, so that
entry remains explicitly unavailable. This does not block known products or turn
similarly named packages into substitutes. See the Speckit acceptance record for
nine public distribution checks and the separate native/Docker lifecycle evidence.
