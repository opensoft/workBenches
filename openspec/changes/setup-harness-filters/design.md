# Filter design

Brett's four-column follow-up supersedes the six-row checkbox interaction (2026-10-23, T039L). Keep Type, Region, Access and Native in four aligned columns above live results. Each shows its title and one current value. Type starts at Frontier; other columns start at All. Type also offers Open, Closed, All and Unknown. Open/Closed describe supported open-weight/closed models, as Brett clarified, independently of the harness license and curated Frontier ownership. A harness can match both; partial metadata remains Unknown. Via models/plugins and ownership Group are no longer filter controls; keep their catalog/About metadata.

F moves focus between filters and results. In filter focus, Left/Right (or Tab/Shift+Tab) wraps across columns; Up/Down wraps values and applies them immediately. Space advances the current value; D does nothing. Left/Right outside filters retain step navigation; Enter retains Review. C clears to All in all four columns, while a new session defaults Type to Frontier. Each dimension is single-choice, all four combine with AND. A product may satisfy Subscription and API on separate selections. No filter action changes queued installation actions.

The pure-Bash library caches membership from generated metadata. Keep the focused product if visible, otherwise focus the first match. Empty results have no stale item About or action. Each combination retains its own result-list window. P/G, refresh and ordinary step navigation retain values, focused column and About/result state. Four columns remain visible down to 36 columns; compact labels are explained in focused-filter About. The list and About share the existing height budget; no renderer subprocesses.

Internal catalog schema 2 gains a qualified model-weight record for CLI entries. Compiler validation checks model-weight values/provenance as for access/native/via and emits exactly four visible dimensions. Retain the separate native/routed records, ownership groups and detection inventory. Private plans remain schemaVersion 1 with unchanged IDs/actions. Deterministic snapshots, locale/size fixtures, queue/state guards and no-fork tests cover the change.
