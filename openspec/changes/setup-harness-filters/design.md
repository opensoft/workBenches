# Filter design

A reusable pure-Bash library owns CLI filter state, membership matching and panel rendering. The existing category/list/About layout remains. F replaces the group picker with six rows (Frontier, Region, Access, Native, Via models/plugins, Group); selected options use checkboxes, Group uses one radio choice. Tab moves the focused option within its row and Space selects it. A horizontal option viewport retains the focused token at narrow widths. Up/Down changes rows. F returns to the result list and C clears all dimensions. The panel has its own responsive row viewport and shares About/footers. A collapsed summary shows active dimensions and result count above the list. No keypress spawns processes.

Membership is cached against canonical ordered option selections and existing group. OR applies within multi-select dimensions; AND applies between dimensions. Unknown is matched only by an explicit Unknown choice; no active choices means the entire dimension passes. Curated Frontier membership uses an explicit lab list (with an editorial note/date), never provider access or region inference. Region uses the existing qualified catalog region. All supplied terminal coding agents have a user-inventory LLM baseline; other tags require separate evidence. Native and external integration tags have separate records and route notes. An external CLI route is not a bundled feature or evidence of installed/authorized integration.

Each result set gets its own list offset. Keep the selected product if still visible; otherwise focus the first match. If there are no matches, no stale item is rendered, described or selectable. Existing queued changes remain visible in Review, including items hidden by filters. C resets only filters/group. P/G stores selections, row/option/viewport state and group along with existing item/About targets; refresh retains them. Changing step can retain filters, while a new session starts with no active filters. Group quick views remain available as a filter dimension.

Catalog schema 2 is internal presentation data only; selection plans remain schemaVersion 1 with unchanged keys/actions. The compiler validates frontier lab IDs, facet values, provenance, dates, sources and CLI-only applicability, then emits Bash maps for the filter library and enriched About. Its generated Python detection data is unchanged in purpose. Snapshots are checked in fixtures/CI. Feature fixtures copy the additional library; the no-fork guard includes the library with no exemptions.
