## Qualification and release interpretation

Start with local profiles/login/persistence, then qualified credential retrieval,
then company synchronization. Keep unqualified OAuth recovery/sharing/refresh
disabled; local OAuth support does not certify remote custody. Do not weaken
independent account binding to achieve a release target.

The plan names Kimi Platform API-key and GLM Coding Plan API-key restoration
through existing Azure Key Vault as the initial minimum M2 acceptance targets,
with native Linux/WSL evidence required for the platforms claimed. Other stores,
GLM standard API and company modes have separate eligibility. These are future
qualification targets, not established capabilities or authorization to provision
infrastructure. Zero enabled retrieval rows is an M1-only outcome.
