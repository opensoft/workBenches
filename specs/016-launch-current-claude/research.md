# Research: Launch only the newest published Claude Code

- **Decision**: Resolve through `claude-current --porcelain` and start the `path=` it prints, reading `version=` for the hand-off. **Rationale**: The home ruling puts the resolver in `opensoft/openRepoTools`, and design.md Decision 1 has this repository call it from `PATH`. Porcelain is the machine form, and its stderr line is the human one. **Alternative**: Parse the human line, or re-read `--version` here. Rejected: that duplicates the resolver, and the contract says not to print a copy of its line.
- **Decision**: The resolver's exit status decides. 0 starts the path, 2 refuses with the resolver's message already printed, 1 is `Claude CLI not found.` with status 1 as before. Any other status, or an exit 0 without an absolute executable path, refuses naming what it got. **Rationale**: Decision 4, step 3. A resolver that answers outside its contract must not start something unverified. **Alternative**: Fall back to the native ordering on a resolver error. Rejected: it would hide a broken install behind a launch that looks normal.
- **Decision**: `CLAUDE_BIN` equal to `CLAUDE_RESOLVED_BIN` is the launcher's own earlier resolution, so it is resolved again; any other nonempty `CLAUDE_BIN` is a pin. The launcher exports the pair after every resolution, fallback included. **Rationale**: The ratified scenario "Inherited resolution is not a pin". A session carries the pair to a `/ctx` respawn, a nested `pclaude`, or a tmux server that captured it. Without the mark, a resolution would become a pin for ever. **Alternative**: Never export `CLAUDE_BIN` into the session. Rejected: `lane-start` needs it, and a tmux server still captures what the tmux child was given.
- **Decision**: Resolve lazily, once, in the process that starts Claude. From outside tmux, the parent only wraps tmux, and it threads a pin and nothing else: an empty `CLAUDE_BIN`, with the marker and version cleared, tells the child to resolve. A session launch resolves after the lane is settled. **Rationale**: One `npm view` per launch. A pick the lane picker hands to another launch is resolved there, not here as well. **Alternative**: Resolve in the parent and hand the child the triple. Rejected by the brief's design record ("lazy in the act1 child"). It would also need a third meaning for the pair, a "fresh hand-off" that the contract does not define.
- **Decision**: `--offline` for every invocation `claude_args_start_session` already calls a non-conversation (`mcp`, `plugin`, `doctor`, `install`, `update`, `--help`, `--version`, `--print`), and for `login` and `status`. **Rationale**: Point 2 is about the models a session sees. One list decides the tmux wrap, the lane default and now the network check. **Alternative**: Check npm on every invocation. Rejected: auth and scripted one-shots would wait on the network for nothing they use.
- **Decision**: Hand `CLAUDE_VERIFIED_VERSION` to `lane-start` as an `env` prefix on that one call. It is never exported, and any value in the environment is dropped when the launcher starts. **Rationale**: The contract says it never reaches a running session. `lane-start` records it and removes it itself; the direct `exec` must not carry it. The prefix also leaves the `exec` line, which a suite pins byte for byte, unchanged. **Alternative**: Export it and unset it before `exec`. Rejected: one missed path would leak it.
- **Decision**: For every resolver status (verified, ahead, unverified, stale-allowed), hand `CLAUDE_VERIFIED_VERSION` the version the resolver read. **Rationale**: This is the brief's contract, and the ratified "The launch says what launched" scenario requires it for a verified launch and forbids it for no other. R4, which would say so in the spec, is held as RULING NEEDED.
- **Decision**: Without `claude-current`, use the #109 native ordering, then the pre-change `PATH` lookup, with one notice: `pclaude: claude-current is not installed, so this launch of <path> is not verified against npm; install it with openRepoTools --install`. A pin prints nothing. **Rationale**: Decision 4, step 4, and the scenario "No usable native version". A host without openRepoTools must still launch. **Alternative**: Refuse and name the install. Rejected by the ratified text.
- **Decision**: Spell the act that places the resolver once, as `claude_current_install_act='openRepoTools --install'`, print the variable in the two messages that name it, and exclude that one assignment from `R-A11-13`'s spelling count in `devcontainer.test/test-claude-profile-amendment-11.sh`, beside the exclusion #93 added for the name guard's notice. **Rationale**: The ratified scenario "No usable native version" requires the notice to name the command that installs the resolver, and `R-A11-13` compares how often the launcher's executable text spells `openRepoTools` with how often `lane_start_install_act` does. `claude-current` ships in openRepoTools itself, so its act is not the lane tools' act that rule is about. The exclusion matches the whole assignment line (`grep -Fxv`), so a literal second spelling still fails the suite, as a mutant shows. **Alternative**: Name the resolver's act through `lane_start_install_act`. Rejected: that function answers the lane tools' act, which on an openRepoTools without the lane tools is the `link-estates` interval act, and the suite pins it to exactly two callers.
- **Decision**: No launcher-side timeout around the resolver. **Rationale**: The resolver bounds its own npm read (10 s) and its own locked update. An outer kill could interrupt an npm install midway.
- **Decision**: When a resolution ends the launch and this process is the only command of its tmux pane, set the pane's `remain-on-exit` before exiting. **Rationale**: The `R-A11-4` fence: a pane that closes over its own refusal hides the reason, and a refused child in a fresh tmux session would show only `[exited]`. The launch still exits with the refusal's status. **Alternative**: Wait for Enter. Rejected: it would block an unattended `/ctx` respawn.
- **Decision**: The Layer 3 version comes from `docker run --rm --entrypoint="" <pinned base> sh -c 'npm view @anthropic-ai/claude-code version'`, bounded by `WORKBENCHES_CLAUDE_VERSION_PROBE_TIMEOUT_SECONDS` (default 30). It is validated strictly as an exact version and passed as `--build-arg CLAUDE_CODE_VERSION`. `--claude-version` overrides it. **Rationale**: Decision 2. The build host needs no npm, the lookup and `FROM` share one immutable reference, and a failed or strange answer ends the build naming the lookup. **Alternative**: The base image's version, the Codex shape. Rejected by point 1: npm latest.
- **Decision**: Declare `ARG CLAUDE_CODE_VERSION` immediately before its `RUN`, after the Codex overlay. **Rationale**: Docker invalidates the cache from the first `RUN` after an `ARG` whose value changed, so a new release rebuilds only that step and what follows it.
- **Decision**: Run the package's `install.cjs` only when `claude --version` does not yet report the version, then require `command -v claude` to resolve under `$NPM_CONFIG_PREFIX` and `--version` to report the version. **Rationale**: Decision 3. npm 12's install-script policy can skip the native-binary hook, and Layer 0 runs it for the same reason.
- **Decision**: The status line passes `(.version // "")` as the last field of its one `jq` array, calls the check with `--pid "$PPID"` and, when the JSON has a version, `--running <version>`, and prints only the first line of its output. **Rationale**: Claude runs the panel under a `/bin/sh -c` that does not exec it, so `$PPID` is that shell and claude its parent. Passing an empty `--running` could be a usage error that loses the `(deleted)` check. A 1 s bound mirrors the panel's bounded `git` call. **Alternative**: A version-only fallback without `/proc`. Rejected: R5 is not ruled, and the ratified "No process table" scenario says no line.
- **Decision**: Harden the suites this feature extends. The binary-selection suite unsets the hand-off names and `CLAUDE_BIN`, takes its checkout physically, and makes its launcher argument absolute. The status line suites name no restart check. Both Layer 3 mocks answer the new lookup. **Rationale**: Run from a session this launcher started, the suite inherited `CLAUDE_BIN` and started the caller's own claude. Through a symlinked checkout, its entry-point check failed. With a relative launcher argument, `pclaude` fell through to the host's installed launcher. A real restart check would add a fifth panel line under a stale session.
