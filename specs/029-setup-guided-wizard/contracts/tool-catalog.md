# Internal tool catalog contract

Schema version 1, canonical config/setup-tool-catalog.json. IDs are stable lowercase underscore identifiers; each entry belongs to one home category, while tags/additional surfaces capture overlapping roles. Managed IDs are the existing eight Harness/seven Tools components only. References never expand selection or credential-plan allowlists. Categories/groups reference existing entries; every terminal product has exactly one CLI ownership group. Model policy is independent of ownership. Identity, capabilities, metadata verification and executable presence are separate concepts. Sources are HTTPS links; unknown values are explicit and never inferred as unavailable. Fields include developer relationship/region, model policy, terminal modes, execution location, status, lineage, extra surfaces, autonomy/permissions, invokes-agent mechanism, external invocation, delegation, state exchange and parallel execution.

The deterministic compiler validates strings/IDs/URLs and emits shell-quoted static maps plus Python detection data. Generated files contain no executable metadata or workstation paths. Runtime never recompiles or parses JSON in the renderer. Snapshot drift is a verification failure. GUI/CLI/editor-extension identities and regional/legacy SKUs remain distinct; ambiguous detection is manual needs-check. CLI group selection is a view, never an action.
