# Internal tool catalog contract

Schema version 2, canonical config/setup-tool-catalog.json. IDs are stable lowercase underscore identifiers; each entry belongs to one home category, while tags/additional surfaces capture overlapping roles. Managed IDs are the existing eight Harness/seven Tools components only. References never expand selection or credential-plan allowlists. Categories/groups reference existing entries; every terminal product has exactly one CLI ownership group. Model policy is independent of ownership. Identity, capabilities, metadata verification and executable presence are separate concepts. Sources are HTTPS links; unknown values are explicit and never inferred as unavailable. Fields include developer relationship/region, model policy, terminal modes, execution location, status, lineage, extra surfaces, autonomy/permissions, invokes-agent mechanism, external invocation, delegation, state exchange and parallel execution.

The deterministic compiler validates strings/IDs/URLs and emits shell-quoted static maps plus Python detection data. Generated files contain no executable metadata or workstation paths. Runtime never recompiles or parses JSON in the renderer. Snapshot drift is a verification failure. GUI/CLI/editor-extension identities and regional/legacy SKUs remain distinct; ambiguous detection is manual needs-check. CLI ownership groups remain descriptive metadata, never actions.


## Schema 2 facet extension
The catalog is now schemaVersion 2 internally; selection plans remain version 1. CLI entries gain a curated frontier lab ID (or null) and evidence-bearing access/native/via/models records. Model-weight values are open/closed; both can apply. They describe supported model routes independently from the harness license and curated ownership. The four visible facets are Type, Region, Access and Native, each with All/Unknown; Type also includes curated Frontier. Non-CLI entries carry no filter facts. An empty value list means unclassified, not unsupported. Region remains its own existing catalog field. Values are fixed identifiers; source/provenance and route notes qualify claims. Compiled filter maps contain static data only.
