## Format

```text
- [ ] T### [P] [USn] [S|O] Description — files: `path`, `path` — verify: `command`
```

- **`[P]`**: may run in parallel with the other `[P]` tasks of the same phase; no path in `files:` is shared and no unfinished task is needed.
- **`[USn]`**: the spec user story whose acceptance scenarios the task's tests prove. Setup, cross-cutting suite, CI, documentation and landing tasks carry none.
- **Tier**: `[O]` runs on `opus-xhigh`, `[S]` on `sonnet-xhigh` (protocol › Build Tiers). There are **no `[H]` tasks**: the code tree's root `AGENTS.md` (this worktree) declares no `## Governed invariants` section and `plan.md` adds none, so every task is `[S]` at least. A task is `[O]` when the rubric's any-clause holds: a design choice or new interface; a contract, schema or boundary; changes across modules; landing, archiving or another irreversible or procedure-heavy act; security-sensitive work; or an always-governed file (`openspec/` text, `.github/workflows/`, a file that records a pin, digest or measured value such as `release-qa.md`).
- **`files:`** names every path the task may create, change or delete, relative to the feature worktree's root (`git rev-parse --show-toplevel`; the Speckit worktree `../speckit-worktrees/029-setup-guided-wizard` beside the workBenches checkout). A gate task that changes no file names only `specs/029-setup-guided-wizard/tasks.md` (its own tick).
- **`verify:`** is one command, run from the worktree root inside WSL, that exits 0 only when the task is done. A task fails when its verify fails, when its diff touches a path outside `files:`, or when the writer reports doubt or a block.
- **Brett-only gate**: the task needs Brett Heap's action or explicit permission in chat. It is not agent-buildable; an agent prepares it and records Brett's answer, and never acts for him.

## Build rules (apply to every task)

- **Rule S1** (plan › Acceptance-suite impact): a task that changes an asserted interaction updates, in the same task, every local suite that asserts it, keeping every asserted outcome (SC-010).
- **Before each commit** (quickstart §0): no mode change (`git diff --cached --summary`), no CR, `bash -n` on each changed shell file, and `scripts/interactive-setup.sh`, `scripts/launchBench`, `setup.sh` and the other executable scripts stay `100755`. Edits over the `\\wsl.localhost\…` UNC path drop the executable bit; restore it with `chmod +x`.
- **One commit per task**, scoped to its `files:` (plus its own tick here); the commit trailer names the model that actually ran.
- **Rebase** onto `origin/release/1.7.0` at each phase boundary while nothing is pushed (plan Risk 12). After T041 a rebase needs a force push, which is Brett's call.
- **Timing**: if a phase cannot keep the key-response median within 100 ms, stop and return to `/speckit-plan`; never relax FR-060 (plan Risk 1).
- Function and variable names below are the planned ones from `data-model.md` and `research.md`; a builder may choose others only where a later task does not name them.
